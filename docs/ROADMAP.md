# Дорожная карта после сдачи

Правило, по которому составлен порядок: жюри оценивает **корректность среды и оценщика**. Поэтому
сначала идёт то, что доказывает корректность или расширяет её на новые случаи, не трогая контракт,
и только потом то, что меняет модель данных. Всё, что меняет байты эпизодов или контракт, выходит с
новым `SCHEMA_VERSION` и перегенерацией golden-хешей — тест `tests/test_round4_contract_pin.py` не
даст сделать это незаметно.

Риск: **низкий** — новый модуль рядом, контракт и эпизоды не меняются; **средний** — меняются
байты эпизодов (перегенерация, новые golden-хеши); **высокий** — меняется контракт для агента.

### R2. Банковская выписка (полнота)

- Новая открытая таблица `bank.csv`: `bank_row_id, value_date, amount_minor, currency, counterparty_ref, description`.
- Чистая книга: каждая строка выписки ↔ ровно одна пара проводок Dr 1000. Инвариант 6: сумма выписки = обороты 1000.
- Ошибка `unrecorded_receipt`: строка выписки без проводки. `affected_ids = [bank_row_id]`, сумма = сумма строки в base.
- Отвлекающий случай: поступление в последний день, проведённое первым днём следующего периода по политике `bank_value_date`.
- Почему высокий риск: новая таблица в `list_records`, новый ID в доказательствах — меняется контракт агента. Только с `SCHEMA_VERSION = "1.1"`.

### R3. Несколько периодов

- Эпизод = 2–3 периода; `opening_balances.csv` для каждого периода.
- Ошибка `opening_balance_mismatch`: сальдо 1200 на начало периода N ≠ сальдо на конец N−1.
- Взаимодействие с `period_cutoff`: счёт, отсечённый неправильно в N−1, всплывает в N.
- Риск: растут размеры эпизода; бюджет 100 шагов придётся пересчитать (`tools/min_budget.py`).

### R4. Локальная LLM: протокол (записать **до** прогона)

- Модель: открытые веса, файл модели с sha256 в отчёте; запуск локально, без сети.
- Температура 0, фиксированный seed генерации, системный промпт = текст задачи среды (`tools/llm/`), хеш промпта в отчёте.
- Эпизоды: те же 20 dev + 20 свежих seed; бюджет 100 шагов; время на шаг не ограничено, но записывается.
- Отчёт: P/R/F1/награда/шаги рядом с политиками и человеком; разбор сбоев по кодам причин оценщика.
- Низкий балл — не провал: «скрипт решает, LLM пока нет» — это и есть доказательство, что среда не тривиальна.

### R5. Трудность по Rasch

- `tools/rasch.py` уже даёт трудность 15 вариантов ошибок с интервалами.
- Ручка: `difficulty: 0..1` → генератор подбирает состав ошибок так, чтобы средняя измеренная трудность попала в цель.
- Учебная программа: последовательность seed, отсортированная по предсказанной трудности; проверка — на свежих seed предсказанная трудность коррелирует с фактическим F1 `simple_reconcile`.
