# Честные ограничения

1. **Награда не доказывает пригодность для реального аудита.** Это программная задача на
   вымышленных данных, не профессиональное аудиторское заключение. Высокая награда значит
   только «нашёл заложенные генератором искажения с нужными доказательствами».
2. **Мы не обучали веса и не заявляем улучшений модели.** Сравнений «до/после» на отложенных
   данных нет. Есть только базовые скриптовые политики и атаки.
3. **Узкий мир.** 4 типа ошибок, 2 сценария взаимодействия, 11 видов отвлекающих случаев,
   7 счетов плана, 5 валют, 7 часовых поясов. Нет НДС, нескольких юрлиц, кредиторки, складов,
   праздничных дней в календаре курсов (рабочие дни = пн–пт), переплат, частичных возвратов
   иностранных платежей.
4. **Часовые пояса с фиксированным смещением** (без летнего времени); смещения 2026 года зашиты
   в `auditenv/timeutil.py`. Зоны с DST не поддерживаются намеренно (воспроизводимость без tzdata).
5. **Цели мутаций упрощены**: курс и cutoff портятся только у неоплаченных счетов, распределение —
   только у платежей, единственных для своих счетов. Каскадные ошибки (неверный курс счёта,
   который потом оплатили) не моделируются.
6. **Размер.** По умолчанию 120–281 проводка и 57–119 документов (замер на 1 000 эпизодах) —
   ниже «предлагаемых» кейсом 200–2 000 проводок; пресет `stress` даёт 1 350–1 520 проводок.
   Генерация stress‑эпизода 0,3–0,5 с, прогон simple_reconcile ≈ 0,1 с.
7. **Изоляция процесса — не песочница.** Политика работает в отдельном процессе с пустым cwd и
   урезанным окружением и не получает путей к эпизоду, но seccomp/отдельного пользователя нет:
   вредоносная политика в том же контейнере теоретически может прочитать файлы с диска.
   Для официальной проверки жюри запускает свои политики через свой адаптер.
8. **Генератор и решатель написаны одной командой.** Независимость решателя — в том, что он
   работает только по открытым файлам и не видит provenance; общие правила политики (курс,
   период, распределение) он реализует заново. Ошибка в понимании самого правила была бы
   общей для обоих — поэтому правила опубликованы в `policy.json` и `docs/DESIGN.md`.
9. **Перегенерация.** Если обязательный сценарий не удалось внести, берётся следующий под‑seed
   (2 случая на 1 000 эпизодов). Это меняет распределение эпизодов, но фиксируется в
   `provenance.rejections`.
10. **Экспериментальная награда** учитывает только первичные ключи возвращённых записей; ID,
    встреченный внутри другой записи (например, `invoice_refs`), «увиденным» не считается.
11. **simple_reconcile** намеренно прост (см. `docs/FAILURES.md`): 0 % fx‑ошибок в выходные,
    FP на перевыставленных счетах и на дублях с неверным курсом.
12. **Docker‑сборка требует сети** для `pip install` закреплённых версий; сама проверка
    (`docker run --network none ...`) идёт без сети. Замер: 36 с, пик ≈ 70 МиБ при лимите 4 ГБ.
