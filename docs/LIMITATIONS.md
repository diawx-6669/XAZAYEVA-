# Честные ограничения

1. **Награда не доказывает пригодность для реального аудита.** Это программная задача на
   вымышленных данных, не профессиональное аудиторское заключение. Высокая награда значит
   только «нашёл заложенные генератором искажения с нужными доказательствами».
2. **Мы не обучали веса и не заявляем улучшений модели.** Единственное контролируемое сравнение на
   отложенных данных — [`docs/EXPERIMENT.md`](EXPERIMENT.md): выбор одного из 256 вариантов
   скриптовой политики по награде на train переносится на 300 отложенных эпизодов с новой солью
   (+0.84, 95 % ДИ [+0.75; +0.93], плацебо = 0). Это свойство **сигнала среды**, а не модели.
3. **Узкий мир.** 4 типа ошибок, 2 сценария взаимодействия, <!--fact:n_distractors-->14<!--/fact--> видов отвлекающих случаев,
   7 счетов плана, 5 валют, <!--fact:n_timezones-->10<!--/fact--> часовых поясов. Нет НДС, нескольких юрлиц, кредиторки, складов,
   праздничных дней в календаре курсов (рабочие дни = пн–пт), частичных возвратов иностранных
   платежей. Переплата есть только как корректный случай (не как ошибка).
4. **Часовые пояса с фиксированным смещением** (без летнего времени); смещения 2026 года зашиты
   в `auditenv/timeutil.py`. Зоны с DST не поддерживаются намеренно (воспроизводимость без tzdata).
5. **Цели мутаций ограничены там, где иначе сумма перестаёт однозначно выводиться из
   доказательств**: распределение портится только у платежей, единственных для своих счетов и без
   возвратов; `wrong_invoice` — только в базовой валюте; cutoff на оплаченном счёте — только в
   базовой валюте и только вариант `prior_period`. Ошибки на оплаченных документах и на документах
   отвлекающих случаев (аренда, перевыставленный счёт, повтор суммы, ночные/выходные валютные
   документы) есть. Каскадов «ошибка порождает следующую ошибку» сверх двух сценариев нет.
6. **Размер.** Открытые эпизоды: <!--fact:ep_ledger_range-->142–251<!--/fact--> проводок и <!--fact:ep_docs_range-->69–106<!--/fact--> документов —
   ниже «предлагаемых» кейсом 200–2 000 проводок; пресет `stress` даёт 1 350–1 520 проводок.
   Генерация stress‑эпизода 0,3–0,5 с, прогон simple_reconcile ≈ 0,1 с (замер раунда 1).
7. **Изоляция процесса — не полноценная песочница.** Агент работает в отдельной сессии, с rlimits
   (память 1.5 ГиБ, CPU 65 с, 64 файла, запись в файлы невозможна) и — если оценщик запущен от root,
   как в нашем Docker‑образе — от пользователя `nobody`: писать в репозиторий, эталон и журнал
   оценщика он не может (тест атаки‑«писателя»). Но **читать** файлы, доступные всем (в том числе
   `episodes/*/grader/` открытых эпизодов), `nobody` может; seccomp, сетевого и файлового
   пространства имён нет. Без root смены пользователя нет вовсе — остаются только rlimits.
   Для закрытого прогона жюри держит эталон вне образа агента или запускает свои политики через свой адаптер.
8. **Генератор и решатель написаны одной командой.** Независимость решателя — в том, что он
   работает только по открытым файлам и не видит provenance; общие правила политики (курс,
   период, распределение) он реализует заново. Ошибка в понимании самого правила была бы
   общей для обоих — поэтому правила опубликованы в `policy.json` и `docs/DESIGN.md`.
9. **Перегенерация.** Если обязательный сценарий не удалось внести, берётся следующий под‑seed
   (2 случая на 1 000 эпизодов). Это меняет распределение эпизодов, но фиксируется в
   `provenance.rejections`.
10. **Экспериментальная награда** учитывает только первичные ключи возвращённых записей; ID,
    встреченный внутри другой записи (например, `invoice_refs`), «увиденным» не считается.
11. **simple_reconcile** намеренно прост (см. `docs/FAILURES.md`): 0 % fx‑ошибок в выходные,
    не видит `wrong_invoice`, FP на перевыставленных счетах, на законных переплатах и на дублях с
    неверным курсом; на чистых книгах почти всегда −1.
12. **`config_hash` в manifest различает конфиги.** Политика, обученная на открытых эпизодах,
    может выучить априорную частоту ошибок для известного хеша (например, у `clean-only` ошибок
    нет никогда). Чистые эпизоды есть и в смешанных конфигах (`dev-mixed`: 25 %), а закрытые
    прогоны жюри используют новые сочетания параметров, т. е. новые хеши.
13. **Без соли seed восстановим.** Для открытых эпизодов это нормально (seed опубликованы), для
    закрытых прогонов нужно задать `AUDITENV_SEED_SALT` (см. README).
14. **Docker‑сборка требует сети** для `pip install` закреплённых версий; сама проверка
    (`docker run --network none ...`) идёт без сети. Базовый образ закреплён по дайджесту.
15. **Независимый проверяльщик написан той же командой.** Он не импортирует `auditenv` и читает
    правила из `policy.json` и текста кейса, но общее неверное понимание правила у нас обоих он не
    поймает. Ручной аудит по `docs/MANUAL_AUDIT.md` — третья, человеческая линия проверки.
16. **Детектор поверхностных признаков** проверяет конечный список признаков (ниже). Агент может
    найти признак, о котором мы не подумали; порог 0.6/0.6 — наш выбор, а не стандарт.
17. **Тест детерминизма между интерпретаторами** запускается на тех версиях Python, где установлены
    закреплённые зависимости (здесь — только 3.11; в образе — только 3.11).

## Поверхностные признаки не отделяют ошибки (тест-сторож `tests/test_surface.py`)

Ленивый агент может искать не расхождения, а «приметы»: оплачен ли документ, ночное ли время,
записано ли время в UTC, не совпадает ли `service_period` с месяцем выписки, есть ли слово «rent»,
единственный ли платёж, необычный ли префикс ID. Для каждого признака мы меряем, насколько он
**сам по себе** отделяет ошибочные документы (`affected_ids` эталона) от корректных:
precision = P(ошибка | признак), recall = P(признак | ошибка), по всем ошибкам и по каждому типу.
Тест падает, если хоть где‑то обе величины > 0.6. Генератор держит это так: ошибки бывают и на
оплаченных документах (B1), есть корректные ночные валютные документы (B2), в каждом эпизоде есть
корректные «двойники» каждого типа ошибки (B5), дубль выписывается в рабочие часы.
