# Эксперимент: даёт ли среда обучаемый сигнал? (протокол зафиксирован ДО прогона)

Этот файл закоммичен **до** запуска `make experiment`; результаты дописываются ниже отдельным
коммитом и публикуются при любом исходе, в том числе нулевом.

## Вопрос и формулировка

Вопрос: если выбирать стратегию **по награде среды** на train‑эпизодах, становится ли награда
лучше на **отложенных** эпизодах, сгенерированных с новой солью? Положительный ответ значит
«**среда даёт обучаемый сигнал**». Мы **не** обучаем веса и **не** утверждаем, что «модель
улучшилась»: «обучение» здесь — выбор одного из 256 вариантов скриптовой политики.

## Протокол

| Элемент | Значение |
|---|---|
| Ветви (arms) | `simple_reconcile` с любым подмножеством 4 правил обнаружения (`dup`, `alloc`, `fx`, `cutoff`) × любое подмножество 4 уточнений (`fx_prev_business_day`, `credit_note_aware`, `overpayment_aware`, `skip_dup_in_fx`) = 256 ветвей |
| Базовая политика | официальный `simple_reconcile`: `{alloc, cutoff, dup, fx}` без уточнений |
| Выбор | successive halving по средней общей награде на 120 train‑эпизодах: 6 открытых конфигов × seed 600000–600019, без соли; старт 8 эпизодов на ветвь, каждый раунд — половина ветвей и вдвое больше эпизодов; ничья — по имени ветви |
| Проверка | **один** прогон на 300 отложенных эпизодах: 6 конфигов × seed 700000–700049, соль `auditenv-E6-heldout-2026-11-20` (нигде раньше не использовалась) |
| Метрика | средняя общая награда `clip(2·F1 − 1 − 0.002·steps, −1, 1)` |
| Статистика | парные разности (выбранная − базовая) по эпизодам; 95 % доверительный интервал парным бутстрепом, B = 10 000, seed 12345 |
| Решение | «сигнал есть», если нижняя граница интервала > 0; иначе «нет свидетельств» |
| Негативный контроль | ветвь‑плацебо (базовая + правило `placebo`, не меняющее ничего) против базовой на тех же эпизодах: разность должна быть ровно 0 — проверка, что конвейер сам не создаёт различий |
| Запуск | `make experiment` (≈ 1 мин); в `make check` не входит; результат — `reports/experiment.json` |

## Угрозы валидности (заранее)

* Отложенные эпизоды из тех же 6 открытых конфигов: обобщение на **новые сочетания параметров**
  этим не проверяется.
* Выбор и уточнения придуманы нами, зная слабости `simple_reconcile` (`docs/FAILURES.md`):
  результат показывает, что сигнал награды **отличает** лучшие правила, а не что их можно найти
  без подсказки.
* Один прогон, одна соль: разброс между солями не оценивается.

## Результаты

Прогон 2026‑11‑20, `make experiment` (≈ 34 с). Сырые числа — `reports/experiment.json`.

**Отклонение от протокола:** первый запуск упал до получения каких‑либо чисел (политика не
вызывала `reset()` в конструкторе); исправлено в коде политики, протокол не менялся, повторный
запуск — единственный, давший результаты.

Отбор (successive halving, 6016 оценок «ветвь × эпизод» на 120 train‑эпизодах):

Отложенные 300 эпизодов (новая соль), один прогон:

| | Средняя награда |
|---|---|
| базовая `simple_reconcile` | +0.132 |
| выбранная по награде | +0.974 |
| **разность (парная)** | **+0.842, 95 % ДИ [+0.754; +0.930]** |
| негативный контроль: плацебо − базовая | +0.000, 95 % ДИ [+0.000; +0.000] |

**Вывод (в формулировке протокола):** нижняя граница интервала > 0, значит, **среда даёт
обучаемый сигнал**: выбор по её награде на train переносится на отложенные эпизоды с новой
солью. Контроль‑плацебо даёт ровно 0 — конвейер сам различий не создаёт. Это **не** утверждение
об улучшении модели: веса не обучались, выбирался один из 256 вариантов скриптовой политики, а
варианты придуманы нами со знанием её слабостей (см. «Угрозы валидности» выше). Выбранная ветвь
всё ещё не видит `wrong_invoice` — потолок 1.0 не достигнут.
