# Безопасность данных: в AuditEnv нет реальных данных

Все компании, клиенты, счета, платежи и суммы **сгенерированы**. Клиенты — это только случайные
ID (`CUST-…`, `CP-…`), без имён, адресов, реквизитов и контактов; описания строк счёта берутся из
короткого фиксированного списка услуг (`Consulting services`, `Software license`, …) в
`auditenv/generator/story.py`; курсы — случайное блуждание, а не реальные котировки. Реальных
платежей, банковских счетов и персональных данных в репозитории нет, и сеть среде не нужна.

## Как это проверено

`tools/pii_scan.py` — сканер, который **не доверяет генератору** и ищет признаки реальных данных
во всех строковых значениях эпизодов и записанных траекторий:

| Что ищем | Шаблон | Проверка, отсекающая случайные совпадения |
|---|---|---|
| Номер платёжной карты | 13–19 цифр подряд или группами через пробел/дефис | алгоритм Луна |
| IBAN | 2 буквы + 2 контрольные цифры + 11–30 букв/цифр | ISO 13616 mod‑97 |
| БИН/ИИН Казахстана | ровно 12 цифр | официальная контрольная сумма (веса 1–11, при остатке 10 — веса 3–11, 1, 2) |
| E‑mail | `имя@домен.зона` | — |
| Телефон | `+7 …` и другие `+код` с 10–15 цифрами | — |
| URL | `http(s)://`, `ftp://`, `www.` | — |

| Команда | Что сканирует | Время |
|---|---|---|
| `make pii-scan` | 500 свежих эпизодов (6 конфигов, seed 600000–600499) + 20 открытых эпизодов + все строки `trajectories/trajectories.jsonl` | ~25 с |
| `pytest -q tests/test_round4_pii.py` (входит в `make check`) | 12 свежих эпизодов, контрольные суммы на известных значениях, **позитивный контроль** (подложенные карта, IBAN, ИИН, e‑mail, телефон, URL находятся все шесть), отсутствие срабатываний на наших ID, курсах и датах | ~1 с |

Результат на момент сдачи: **0 срабатываний** на 520 эпизодах (34 МБ) и 1195 строках траекторий.

## Сужение шаблонов (и почему оно честное)

Денежные колонки (`debit_minor`, `credit_minor`, `amount_minor`, `total_minor`, `unit_price_minor`,
`quantity`) по схеме — целые числа; 16‑значная сумма — это деньги, а не номер карты, поэтому они не
сканируются как текст. Всё остальное (ID, описания, даты, курсы, ключи JSON, наблюдения агента)
сканируется. Замер: даже **без** этого сужения на 100 эпизодах срабатываний 0 — сужение
защищает от будущих ложных срабатываний на больших суммах (пресет `stress`, валюта JPY), а не
прячет текущие. Наши ID не похожи на реальные реквизиты: в них есть дефис и префикс, а
непрозрачные ID двойников (`transform --opaque-ids`) сканер тоже не принимает за реквизиты (замер: 100 двойников `dev-mixed` — 0 срабатываний; в тестах — 3).

* Окружение и командная строка оценщика — `tests/test_conceal.py`, `docs/ADAPTER.md`.
* Секреты в истории git — `make prepublish` (`docs/HOTFIX.md`).
