# FAQ для жюри: «почему так?»

Короткие ответы на вопросы, которые обычно задают на защите. В каждом — где это проверено.

**1. Почему допуск по сумме ровно ±1 минимальная единица?**
Он терпит честную разницу округления при пересчёте другим порядком операций и ничего не даёт перебору сумм:
все искажения ≥ 100 единиц. Измерено при допуске 0/1/2/5/100 — `reports/tolerance.md`;
граница — `tests/test_reward.py::test_tolerance_boundary`.

**2. Зачем доказательства, если тип, ID и сумма уже верны?**
Чтобы «знать ответ» (угадать, подсмотреть) не равнялось «доказать по записям». Без требования атака,
знающая суммы, получила бы +1.30 к награде — `reports/ablation_evidence.md`;
`tests/test_reward.py::test_guessed_id_without_evidence_is_fp`.

**3. Почему один ID в `affected_ids`, а не пара «оригинал + дубль»?**
Один ID однозначен и выводится из открытых данных правилом «более поздний `issued_at`», опубликованным в задаче
агента. Подробно — `docs/DESIGN.md`, раздел 3.

**4. Почему сумма — в базовой валюте?**
Книга целиком в базовой валюте, а разные валюты нельзя сравнивать без курса. Неверная валюта — FP:
`tests/test_reward.py::test_wrong_currency_is_fp`.

**5. Как разрешаются ничьи при сопоставлении?**
Максимальное паросочетание (Кун); вопросы — по возрастанию `issue_id`, выводы — по индексу:
`tests/test_reward.py::test_tie_break_smallest_issue_then_index`. Полный перебор 85 008 малых случаев — 0 нарушений
(`reports/reward_exhaustive.md`).

**6. Что, если агент зависнет или выберет все 100 шагов?**
Любой обрыв — пустой ответ за полный бюджет (100 шагов): зависнуть никогда не выгоднее, чем честно ответить
(находка симуляции жюри, `docs/FAILURES.md` п. 16; `tests/test_contract.py::test_timeout_on_clean_book_is_charged_full_budget`).

**7. Генератор открыт — почему агент не восстановит эталон перебором seed?**
Закрытые эпизоды солятся секретом `AUDITENV_SEED_SALT`, который не попадает к агенту ни через окружение, ни через
командную строку оценщика: `tests/test_leaks.py::test_seed_salt_blocks_seed_bruteforce`, `tests/test_conceal.py`.

**8. Не отделяет ли ошибки какой‑нибудь простой признак (сумма, время, валюта)?**
Нет: в каждом эпизоде есть корректный «двойник» каждого типа ошибки; детектор поверхностных признаков на 300
эпизодах ничего не находит — `tests/test_surface.py::test_no_surface_feature_is_a_shortcut`.

**9. Откуда уверенность, что эталон верен?**
Три независимые проверки: решатель по открытым данным (`grader/validate_truth.py`), отдельный проверяльщик без
`import auditenv` на 540 эпизодах (`tools/verify_independent.py`) и откат мутаций по provenance
(`verify-provenance`). Плюс компании, собранные вручную (`tests/fixtures/`), и пересчёт сумм по снимкам
«до/после» в `python -m auditenv explain`.

**10. Почему `explanation` вообще есть, если не влияет на награду?**
Кейс требует поле; влияние текста на награду открыло бы путь «убедить оценщика». Проверено атакой
`persuasive_wrong` и `tests/test_reward.py::test_explanation_has_no_effect`.

**11. Хватит ли 20 скрытых эпизодов, чтобы различить политики?**
Для политик разного класса — да; для близких (Δ ≈ 0.05–0.1) — нет, нужен больший парный набор
(`reports/power.md`). Прогноз результатов 4 политик до прогона жюри — `docs/PREDICTION.md`.

**12. Воспроизводится ли всё на другой машине?**
Да: 20 открытых эпизодов, golden‑эпизоды и детерминированная часть self‑check совпадают побайтно на Python 3.11,
3.12 и 3.13 при разных `PYTHONHASHSEED`, `TZ`, `LANG` (`reports/repro_cross_python.md`); сверить свою машину —
`make repro-cert-check`.
