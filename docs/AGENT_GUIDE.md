# Памятка автору агента

Для тех, кто подключает свою политику к AuditEnv (протокол — `docs/ADAPTER.md`, контракт — `docs/CONTRACT.md`).
Здесь — как не терять шаги и баллы. Все числа — из отчётов репозитория.

## 1. Порядок работы, который окупается

1. **Прочитайте политику**: `get_record(table="policy", id="policy")` — 1 шаг. В ней правило курса (местная дата
   транзакции, при отсутствии курса — предыдущий рабочий день), граница периода с часовым поясом и правило
   распределения оплат. ID `policy` пригодится в доказательствах для `fx_rate`, `period_cutoff` и `vat_error` (правило `policy.vat`).
2. **Листайте таблицы страницами по 50**: `list_records` с `next_cursor`. На открытых размерах вся книга — 11–16
   страниц (`simple_reconcile` тратит 11–16 шагов из 100). Страница дешевле точечных запросов, когда
   доказательств много.
3. **Ищите кандидатов** по правилам ниже, **пересчитайте суммы** (калькулятор считает в `Decimal`; деньги — целые
   минимальные единицы базовой валюты).
4. **Отправьте выводы с одним полным набором доказательств** на каждую ошибку. На чистой книге пустой список —
   правильный ответ (+1 минус шаги).

Минимум, который вообще нужен, если знать, куда смотреть: медиана 5, максимум 13 вызовов на эпизод
(`reports/min_budget.md`). Шаг стоит 0.002, пропуск одной из n ошибок — 2/(2n − 1) (`reports/reward_table.md`).

## 2. Что должно совпасть для TP

| Поле | Правило | Частая ошибка |
|---|---|---|
| `type` | один из 4 типов | перебор нескольких типов на одном ID — остальные идут в FP (`wrong_type`) |
| `affected_ids` | ровно канонический ID: дубль — `invoice_id` **более позднего** счёта; распределение — `payment_id`; курс — ID пересчитанного документа; cutoff — `invoice_id` | лишний ID, ID строки проводки, `doc_id` вместо `invoice_id` (`ids_mismatch`) |
| `claimed_amount_minor` | модуль искажения в **базовой** валюте, ±1 | сумма в валюте документа, знак, округление не по `ROUND_HALF_EVEN` (`amount_out_of_tolerance`) |
| `currency` | базовая валюта эпизода | валюта документа (`currency_mismatch`) |
| `evidence_ids` | содержит **целиком** хотя бы один набор (≤ 6 ID, лимит 10 на вывод) | не хватает строки проводки, курса или `policy` (`evidence_incomplete`) |
| — | один вывод на ошибку | повтор того же вывода (`duplicate_finding`) |

Коды причин — те, что пишет журнал оценщика; свой ответ можно проверить офлайн:
`python -m auditenv grade episodes/dev/<episode_id> my.json` (печатает код для каждого вывода). Готовые верные
примеры по каждому типу — `docs/FINDINGS_EXAMPLES.md`.

## 3. Ловушки (корректные «двойники» есть в каждом эпизоде)

* **UTC‑ловушка.** Время документов записано то в местном смещении, то в UTC. Дата для курса и для периода —
  **местная** (`2026-10-31T21:30:00+00:00` в Алматы — это уже 1 ноября).
* **Выходные.** Курсов на выходные нет: берите предыдущий рабочий день. Наш `simple_reconcile` этого не делает и
  пропускает все такие fx‑ошибки (`docs/FAILURES.md`, раздел 2).
* **Credit note и перевыставление.** Счёт, отменённый credit note (`cancels_invoice_id` в строках), и новый счёт с
  теми же строками — **не** дубль.
* **Аренда каждый месяц** — одинаковая сумма, но разный `service_period`: не дубль.
* **Переплата** на 2400 — законна; ошибка распределения — когда часть платежа, которая должна была погасить счёт,
  легла на 2400. И наоборот: `wrong_invoice` (погашен чужой счёт того же клиента) на 2400 не виден вовсе.
* **Частичная оплата с открытым остатком, оплата частями, один платёж на 2–3 счёта, комиссия банка, разница
  округления в 1 единицу, операции в 23:50** — всё это корректно.

## 4. Чего не делать

* Не отправляйте одно и то же несколько раз и не перебирайте типы или суммы: взаимно однозначное сопоставление
  засчитает один вывод, остальные — FP (`site/attacks.html`, `reports/tolerance.md`).
* Не пишите «убедительный» `explanation` вместо доказательств: текст на награду не влияет.
* Не зависайте и не тяните до 100 шагов: любой обрыв оценивается как пустой ответ за полный бюджет (100 шагов).
* Не рассчитывайте на заученные ID: в закрытых эпизодах и у двойников (`transform --opaque-ids`) ID другие.

## 5. Как проверить себя до жюри

```text
python -m auditenv run --policy-cmd "python my_agent.py" --seed 12 --config dev-mixed          # один эпизод, train
python -m auditenv jury-pairs --policy-cmd "python my_agent.py" --n 20                          # 20 пар с непрозрачными ID
python -m auditenv explain episodes/dev/<episode_id>                                            # где были ошибки (HTML)
```

Функции для LLM‑агента (OpenAI/Anthropic function calling), системный промт и два примера диалога — `tools/llm/`.
