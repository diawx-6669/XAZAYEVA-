# Datasheet: открытые эпизоды AuditEnv

По шаблону *Datasheets for Datasets* (Gebru et al., 2018/2021). Все числа в этом файле стоят в
невидимых маркерах `<!--fact:…-->` и пересчитываются из закоммиченных эпизодов командой
`python -m auditenv docs-check` (функция `auditenv/docs_check.py::_datasheet`); расхождение
роняет `make check`. Набор данных — **открытые** эпизоды `episodes/train/` и `episodes/dev/`;
закрытые эпизоды жюри генерируются тем же кодом с секретной солью и здесь не описаны.

## 1. Мотивация

* **Зачем создан.** Чтобы обучать и честно оценивать ИИ‑аудитора с подкреплением: в книгах
  вымышленной компании заложены ошибки с известной причиной и суммой, агент должен найти их с
  доказательствами. Это кейс Genesis Hackathon (трек FinTech), `docs/CASE.md`.
* **Кто создал.** Команда из 4 человек (`docs/SUBMISSION_FORM.md`); код в основном написан
  Claude Code по нашему ТЗ (`docs/AI_USAGE.md`).
* **Финансирование.** Нет; данные не основаны ни на чьих реальных книгах.

## 3. Процесс сбора

* **Как получены.** Синтетически: `python -m auditenv export` по списку `(config, seed)` из
  `configs/splits.json`; генератор детерминирован (`random.Random(sha256(seed:stream:attempt))`).
  Дайджесты открытой и закрытой частей — в `episodes/*/index.json`.
* **Проверка.** Сканер совпадений перегенерирует эпизод, если решатель находит «ошибку» в чистой
  книге; эталон независимо подтверждается `tools/verify_independent.py`; мутации откатываются по
  provenance (`verify-provenance`).
* **Люди.** Не участвовали в генерации; вручную сверены 3 dev‑эпизода (`docs/MANUAL_AUDIT.md`) и
  собраны отдельные компании в Google Таблицах (`tests/fixtures/`).

## 4. Предобработка

Нет: файлы — прямой канонический вывод генератора (`sort_keys`, `\n`, деньги — целые минимальные
единицы, курсы — десятичные строки). Порядок строк задаётся отдельным потоком `order`.

## 5. Использование

* **Для чего.** Обучение и оценка агентов‑аудиторов в среде `AuditEnv` (5 инструментов, ≤ 100 шагов).
  `train/` — для подбора и отладки, `dev/` — для сравнения; финальная оценка — на закрытых эпизодах жюри.
* **Для чего не годится.** Не является аудиторским заключением и не отражает реальную отрасль,
  налоги или МСФО; узкий мир из 4 типов ошибок (`docs/LIMITATIONS.md`). Высокая награда не
  означает пригодность для реального аудита.
* **Риски.** Переобучение на открытых seed: генератор открыт, поэтому закрытые эпизоды солятся.

## 6. Распространение

В репозитории под лицензией MIT (`LICENSE`); зависимости и их лицензии — `THIRD_PARTY_NOTICES.md`.
Эпизоды можно пересобрать из seed: `make episodes` даёт побайтно те же файлы (`make repro-cert`).

## 7. Сопровождение

Команда проекта; ошибки — через issues репозитория, горячие исправления — `docs/HOTFIX.md`. Смена
генератора меняет версию конфигов (`configs/LOCK.json`, `configs/CHANGELOG.md`) и golden‑хеши.
