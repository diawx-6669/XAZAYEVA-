## 2. Суть простыми словами

Мы строим **тренажёр для ИИ-аудитора**, как авиасимулятор для пилота.

1. **Генератор** по числу-seed придумывает вымышленную компанию за один отчётный период (1–3 месяца, по конфигу): клиентов, счета, платежи, бухгалтерскую книгу, курсы валют и правила.
2. Сначала всё правильно, потом генератор **специально прячет ошибки** и записывает правильные ответы в секретный файл `truth.json`.
3. **ИИ-агент** через 5 «кнопок» (не больше 100 шагов) читает данные и сдаёт список найденных ошибок с доказательствами.
4. **Оценщик** сравнивает ответ с секретным файлом и выставляет награду от −1 до 1.

Такие тренажёры нужны для обучения с подкреплением (RL): ИИ проходит тысячи экзаменов, видит награду и учится. **Сам ИИ мы не обучаем** — жюри оценивает честность и качество тренажёра, а не ум агента.

## 3. Чего мы НЕ делаем

- Не обучаем модели и не покупаем API-ключи. Официальная проверка идёт без сети, без платных API и без GPU.
- Не делаем UI: за него баллов не дают.
- Не используем реальные финансовые данные. Всё вымышлено, иначе оценивание блокируется.
- Не заявляем «модель стала лучше» без контролируемого сравнения на отложенных данных.

## 4. Финансовые понятия, которые нужно знать

| Термин | Что это |
|---|---|
| Счёт (invoice) | «Клиент должен нам N до даты X» |
| Платёж (payment) | Деньги, которые реально пришли. Могут закрывать один или несколько счетов |
| Книга (ledger) | Журнал проводок: каждое движение денег — дебет и кредит, суммы равны |
| Распределение платежа | Привязка пришедших денег к конкретным счетам |
| FX-курс | Курс валюты на конкретный день. Ledger ведётся в базовой валюте (KZT) |
| Отчётный период | Месяц, в границах которого всё должно быть учтено. Границы — по местному времени |
| Минимальные единицы | Деньги в тиынах или центах, только целые числа: 1500.25 KZT = 150025 |

План счетов: `1000 Cash`, `1200 Accounts Receivable`, `2400 Unapplied Cash`, `4000 Revenue`, `4100 Refunds`, `6500 Bank Fees`, `7900 FX Gain/Loss`.

## 5. Четыре типа ошибок

| Тип | Что случилось | Пример |
|---|---|---|
| `duplicate_invoice` | Один счёт выставлен и проведён дважды | Тот же клиент, те же позиции, дата сдвинута на 0–2 дня |
| `payment_allocation` | Платёж не привязан к счёту или привязан частично | Пришло 1000, к счёту записано 700, а 300 лежит на 2400 |
| `fx_rate` | Валютный документ пересчитан по курсу не того дня или по перевёрнутому курсу | Взят курс пятницы вместо понедельника |
| `period_cutoff` | Документ вне периода попал в период | `2026-10-31T21:30+00:00` — это уже 1 ноября в Астане |

**Взаимодействующие ошибки (2 сценария):**
- `partial_fx_cutoff` — частичный платёж в EUR в последний день периода, по неверному курсу;
- `duplicate_fx` — дубль долларового счёта плюс неверный курс.

**Отвлекающие случаи (не ошибки!):** одинаковая ежемесячная аренда, оплата частями, один платёж на несколько счетов, законная частичная оплата, возврат, банковская комиссия, разница округления в 1 единицу, операция в 23:50 последнего дня, отмена счёта с перевыставлением. Есть и полностью чистые компании без ошибок.

## 6. Как устроен эпизод

```
episode/
  public/                 ← видит агент (только через инструменты)
    manifest.json         описание эпизода, валюты, период, округление
    ledger.csv            проводки (в базовой валюте)
    invoices.jsonl        счета
    payments.jsonl        платежи
    fx.csv                курсы
    policy.json           правила: дата курса, границы периода, округление
  grader/                 ← видит ТОЛЬКО оценщик
    truth.json            правильные ответы и допустимые наборы доказательств
    provenance.json       история генерации и мутаций «до/после»
```

Размер train/dev/закрытых эпизодов: 200–450 проводок, 30–80 документов, 0–6 ошибок (замер: 204–376 и 42–78).

## 7. Инструменты агента

| Действие | Что делает |
|---|---|
| `list_records(table, cursor, limit)` | Страница до 50 строк, курсор непрозрачный |
| `get_record(table, id)` | Одна запись (включая `policy` и `fx:{date}:{src}:{tgt}`) |
| `get_document(doc_id)` | Документ счёта или платежа |
| `calculator(expression)` | Только арифметика: `+ - * /`, скобки, Decimal |
| `submit(findings)` | Сдать ответ, эпизод заканчивается |

Ошибки — только коды: `unknown_tool`, `bad_args`, `not_found`, `invalid_cursor`, `calc_error`, `episode_over`. Любая ошибка тратит шаг.

Режимы: в `train` агент получает итоговую награду, в `eval` он видит reward = 0 и `info = {}`, а итог уходит только в журнал оценщика.

## 8. Награда

```
TP — верный вывод: тип, ID, сумма (±1), валюта и полный набор доказательств
FP — неверный или повторный вывод
FN — пропущенная ошибка

F1     = 2·TP / (2·TP + FP + FN)
reward = clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)
```

- Если эталон пуст и ответ пуст: F1 = 1. Если эталон пуст, а ответ есть: F1 = 0.
- Неверный JSON даёт −1.
- `explanation` на награду не влияет.
- Экспериментальная награда (показывается отдельно) засчитывает TP, только если агент реально видел доказательства.

Разбор 15 атак и того, почему они проигрывают честному ответу: `docs/ATTACKS.md`.

## 9. Политики для демо и проверки

| Политика | Роль |
|---|---|
| `random_explorer` | Случайные действия, пустой ответ |
| `simple_reconcile` | Честный скриптовый аудитор, **основное демо** |
| `flag_all` | Атака «обвинить всё» |
| `oracle` | Читает truth (только для оценщика), показывает максимум награды |
| `attacks.py` | Близнецы, перебор типов и сумм, угадывание ID и т.д. |

## 10. Как жюри ставит баллы (100)

| Критерий | Баллы | Что проверяют |
|---|---|---|
| Контракт и изоляция | 25 | 20 проверок reset/step, схем, лимитов, неверного ввода, утечек |
| Данные и эталон | 25 | 20 закрытых эпизодов: равенства до ошибки, расхождение после, доказательства |
| Надёжность награды | 25 | 20 проверок: сопоставление, чистые случаи, FP, дубли, атаки |
| Воспроизводимость и обобщение | 15 | 20 парных проверок: повтор seed, перестановка и смена ID |
| Инженерия и объяснение | 10 | Запуск одной командой, версии конфигов, траектории, разбор сбоев, честные ограничения |

**Блокирует оценивание:** утечка закрытых данных, запись в оценщик, реальные финансовые данные, неработающее ядро.

Проверка жюри: 20 скрытых эпизодов (5 чистых, 5 со взаимодействующими ошибками) и 20 парных преобразований. Лимиты: Python 3.11, 2 CPU, 4 ГБ RAM, 60 с и 100 шагов на эпизод.
