# Эксперимент E6 v2: обучаемый сигнал на текущем генераторе (протокол зафиксирован ДО прогона)

Этот файл закоммичен **до** запуска `make experiment-v2`; результаты дописываются ниже отдельным
коммитом и публикуются при любом исходе, в том числе нулевом. Первый эксперимент E6
([`EXPERIMENT.md`](EXPERIMENT.md), `reports/experiment.json`) **не трогаем**: он прогнан на генераторе
до слияния с `main` и остаётся как есть.

## Зачем v2

1. Генератор изменился после E6 (размеры эпизодов, построчная выручка, новые варианты ошибок и
   «двойники»). Вывод E6 относится к старому генератору; v2 проверяет его на текущем.
2. Закрываем первую угрозу валидности E6 («отложенные эпизоды из тех же конфигов»): отбор теперь
   идёт только на **4** конфигах, а проверка — на всех **6**, два из которых при отборе не
   встречались.

## Вопрос

Если выбирать стратегию **по награде среды** на train‑эпизодах, становится ли награда лучше на
**отложенных** эпизодах с новой солью, в том числе на конфигах, которых отбор не видел? Мы **не**
обучаем веса и **не** утверждаем, что «модель улучшилась»: «обучение» — выбор одного из 256
вариантов скриптовой политики.

## Протокол

| Элемент | Значение |
|---|---|
| Ветви | те же 256, что в E6: `simple_reconcile` × подмножество правил (`dup`, `alloc`, `fx`, `cutoff`) × подмножество уточнений (`fx_prev_business_day`, `credit_note_aware`, `overpayment_aware`, `skip_dup_in_fx`) |
| Базовая политика | официальный `simple_reconcile`: `{alloc, cutoff, dup, fx}` без уточнений |
| Отбор | successive halving по средней общей награде на 120 train‑эпизодах: **4 конфига** (`train-easy`, `train-global`, `dev-mixed`, `interaction-heavy`) × seed 610000–610029, без соли; старт 8 эпизодов на ветвь, каждый раунд — половина ветвей и вдвое больше эпизодов; ничья — по имени ветви |
| Проверка | **один** прогон на 300 отложенных эпизодах: 6 конфигов × seed 710000–710049, соль `auditenv-E6v2-heldout-2026-11-21` (нигде раньше не использовалась) |
| Основная метрика | средняя общая награда `clip(2·F1 − 1 − 0.002·steps, −1, 1)`, парная разность (выбранная − базовая) по 300 эпизодам |
| Статистика | 95 % доверительный интервал парным бутстрепом, B = 10 000, seed 12345 |
| Решение (основное) | «сигнал есть», если нижняя граница интервала по 300 эпизодам > 0; иначе «нет свидетельств» |
| Вторичный анализ (описательный, на решение не влияет) | (а) та же разность и интервал только на 100 эпизодах конфигов, **не участвовавших в отборе** (`dev-global`, `clean-only`); (б) средние по каждому конфигу |
| Негативный контроль | плацебо‑ветвь (базовая + правило `placebo`, ничего не меняющее) против базовой на тех же 300 эпизодах: разность должна быть ровно 0 |
| Запуск | `make experiment-v2` (`python -m auditenv experiment --protocol E6v2`); в `make check` не входит; результат — `reports/experiment_v2.json` |
| Код | `auditenv/experiment.py::PROTOCOLS["E6v2"]`; тест `tests/test_experiment.py::test_e6v2_protocol_is_new_and_e6_is_frozen` фиксирует константы протокола и то, что E6 не изменился |

## Ожидания (записаны заранее, на решение не влияют)

* На `clean-only` у правильной политики награда около +1, и выигрыш выбранной ветви там возможен
  только за счёт меньшего числа ложных срабатываний базовой — разность может быть около 0.
* Если отбор подстроился под 4 train‑конфига, вторичная разность на невиданных конфигах будет
  заметно меньше основной.

## Угрозы валидности (заранее)

* Невиданные конфиги — всё равно наши конфиги того же генератора; это «новые сочетания
  параметров», а не новая предметная область.
* Ветви придуманы нами со знанием слабостей `simple_reconcile` (`docs/FAILURES.md`): результат
  показывает, что награда **отличает** лучшие правила, а не что их можно найти без подсказки.
* Один прогон, одна соль: разброс между солями не оценивается.
* `clean-only` содержит только чистые книги; вклад этого конфига во вторичный анализ — проверка
  ложных срабатываний, а не обнаружения.
