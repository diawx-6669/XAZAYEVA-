# AuditEnv — краткая записка о дизайне

Раздел 09 кейса просит краткое описание дизайна. Это оно (1–2 страницы); полная версия с
каждым решением и альтернативой — [`docs/DESIGN.md`](DESIGN.md), трактовки контракта —
[`docs/CONTRACT.md`](CONTRACT.md), ограничения — [`docs/LIMITATIONS.md`](LIMITATIONS.md).

## Что это

RL‑среда и оценщик для ИИ‑аудитора. По `(seed, config)` генерируется вымышленная компания за
отчётный период, в книгу вносятся ошибки с записанной причиной, эталон закрыт. Агент за ≤ 100
шагов через 5 инструментов находит ошибки и подтверждает их доказательствами; оценщик вне
процесса агента сравнивает ответ с эталоном. Баллы — за корректность среды и оценщика, а не за
умного агента: обучения моделей нет.

## Поток данных

1. **Скрытая история** (`generator/story.py`): клиенты, курсы на рабочие дни (`Decimal`‑строки),
   счета, оплаты, возвраты, <!--fact:n_distractors-->14<!--/fact--> видов корректных «двойников» ошибок.
2. **Книги** (`books.py`): документы → двойная запись, всё в минимальных единицах (`int`) базовой валюты.
3. **Сканер совпадений**: независимый решатель на чистой книге должен не найти ничего, иначе — следующий под‑seed.
4. **Ошибки** (`errors/*.py`, по модулю на тип) в фиксированном порядке; каждая мутация атомарна
   и пишет «до/после» в `provenance.json`; сумма — разница книги до и после **этой** мутации.
5. **Экспорт**: `public/` (manifest, ledger.csv, invoices.jsonl, payments.jsonl, fx.csv, policy.json)
   и `grader/` (truth.json, provenance.json) раздельно; канонический JSON, `\n`.

Детерминизм: только `random.Random(sha256(seed:stream:attempt))`, потоки `story/naming/order/errors`;
нет `float` для денег, `time.time()`, `uuid4()`, `hash()`. Закрытые seed солятся `AUDITENV_SEED_SALT`.

## Ошибки и эталон

| Тип | Каноничный ID | Сумма | Ломает ровно инвариант |
|---|---|---|---|
| `duplicate_invoice` | `invoice_id` дубля | Dr 1200 дубля | `unique_billing` |
| `payment_allocation` | `payment_id` | нераспределённая часть | `allocation` |
| `fx_rate` | ID документа | \|проведено − правильно\| | `fx_conversion` |
| `period_cutoff` | `invoice_id` | сумма счёта в базе | `period` |

Плюс сценарии `partial_fx_cutoff` и `duplicate_fx` (две ошибки с независимыми суммами). Каждый
issue несёт 1–3 минимальных набора доказательств ≤ 6 ID; по любому набору сумма пересчитывается
только из его записей (`validate_truth.verify_evidence`, независимо — `tools/verify_independent.py`).

## Среда

`reset(seed, config)` / `step(action)` в стиле Gymnasium. Инструменты: `list_records` (≤ 50 строк,
HMAC‑курсоры), `get_record`, `get_document`, `calculator` (AST + `Decimal`, без имён и степеней),
`submit`. Ошибки — только код, каждая тратит шаг; «нет ID» и «чужая таблица» неразличимы.
100 шагов или 60 с → `truncated`. В `eval` награда 0 и `info={}`, итог — только в журнале оценщика
(цепочка хешей).

## Оценщик

Схема findings (`additionalProperties: false`, лимиты) → нормализация ID и валюты → вывод может
совпасть с issue при равных типе, ID, валюте, сумме ±1 и полном наборе доказательств →
максимальное паросочетание (Кун; ничьи — меньший `issue_id`, затем индекс). P, R, F1 по кейсу;
награда `clip(2·F1 − 1 − 0.002·шаги, −1, 1)`; любой обрыв стоит полный бюджет (100 шагов).
Экспериментальная награда (TP только за реально увиденные доказательства) — отдельно.
`explanation` на награду не влияет.

## Почему так (главные решения)

* **Один каноничный ID и одна валюта суммы** — однозначный matcher, ответ выводится из открытых данных.
* **Доказательства обязательны** — угаданный ID без набора = FP; спам ограничен 10 ID на вывод.
* **Двойники каждого типа ошибки в каждом эпизоде** — поверхностный признак не отделяет ошибку
  (детектор признаков на 300 эпизодах, `tests/test_surface.py`).
* **Оценщик вне процесса агента** — эпизод только в памяти оценщика; агент — `python -I -S` с
  пустым cwd, окружением из 3 переменных, rlimits; командная строка оценщика скрыта (`ps`).
